# 数值设计说明

## 1. 设计问题

本项目回答三个问题：不同职业能否在相同资源预算下达到相近的有效输出；职业特色能否通过生存、爆发周期和随机波动体现；敌人强度随等级成长后，战斗节奏是否仍落在目标区间。

体验目标如下：

| 敌人 | 成功击杀 TTK | 目标胜率 | 体验意图 |
|---|---:|---:|---|
| 普通怪 | 8～12 秒 | ≥95% | 快速建立战斗反馈 |
| 精英怪 | 25～35 秒 | 70%～85% | 迫使玩家使用完整技能循环 |
| Boss | 90～120 秒 | 45%～60% | 同时检验输出与生存构筑 |

目标胜率和 TTK 约束同等级三职业阵容的均值，单职业结果用于体现构筑差异；职业平均有效 DPS 差异以 8% 为软上限。该限制不要求技能结构、爆发窗口和承伤完全相同。

## 2. 战斗规则

- 双方在 `t=0` 进入可行动状态，技能命中在 `cast_time` 结束时结算，之后经历 `recovery`。
- CD 从开始释放时计算，资源也在开始释放时扣除；资源按秒连续恢复，在事件发生时惰性更新。
- 命中和闪避为两次独立判定，命中后再判定暴击。
- 同一时间点的所有伤害基于结算前状态计算，再统一扣除生命；双方同时归零记为平局。
- Buff 在技能命中时施加，采用左闭右开区间 `[生效时间, 到期时间)`。
- 有效伤害不超过目标剩余 HP，溢出部分单独记录，DPS 只使用有效伤害。

## 3. 成长与防御

属性按复合成长计算：`Stat(L)=Base×(1+Growth)^(L-1)`。等级本身不直接增加伤害，以免和攻击成长重复放大。

防御倍率为 `K(L)/(K(L)+Defense)`。`K(L)` 随等级线性提高，使同等级防御成长的收益保持稳定，同时保留边际收益递减。该公式连续、单调且不存在负伤害区域，适合做参数扫描。

## 4. 职业差异

- **铁卫**：HP、防御和减伤技能更高，暴击较低，输出分布稳定。
- **风痕游侠**：攻击频率、暴击率和闪避更高，输出 P10～P90 区间更宽。
- **星火术士**：依赖资源与奥能涌动的爆发窗口；错误释放顺序会显著降低收益。

三类行为策略用于区分“数值强度”和“操作策略收益”。固定优先级便于解释；爆发策略允许短暂等待以对齐增益；保守策略在低生命时优先防御，并保持资源下限。

## 5. 统计口径

- 胜率以全部模拟为分母，并同时报告失败、平局和超时率。
- TTK 只统计成功击杀场次；失败场次通过 TTD 和失败率独立呈现，避免把超时伪装成高 TTK。
- 胜率使用 95% Wilson 区间；平均 TTK 使用 2,000 次 Bootstrap 区间。
- P10/P50/P90 用于描述玩家实际感知到的波动，而不是只展示平均值。
- 相同 seed 为每场战斗生成独立子种子，保证跨 worker 数可复现。

## 6. 自动调参边界

优化器只搜索 YAML 明确列出的技能倍率与敌人基础属性。四个目标分别为 TTK 区间偏差、胜率区间偏差、职业 DPS 差异和相对初稿的改动成本。

首轮使用拉丁超立方均匀覆盖搜索空间；第二轮围绕非支配候选做局部采样；最终候选使用更大样本复核。若不存在同时满足所有目标的方案，系统明确标记为“最近候选”，不伪造可行结论。
