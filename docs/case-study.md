# 案例研究：从单向伤害脚本到战斗平衡实验

## 目标定义

初版只计算玩家对敌人的期望伤害和击杀时间。它能检查公式，却不能回答“玩家是否能活下来”“策略是否影响结果”“随机性是否造成体验波动”。本次迭代把项目目标改为：在 1～50 级范围内同时控制战斗时长、生存压力和职业差异。

## 初始失衡

早期模型有三个结构性问题：敌人不会行动，因此玩家 HP、防御和所谓胜率没有实际意义；击杀后仍增加一次攻击间隔，使 TTK 偏大；最后一击完整计入伤害，使 DPS 被溢出伤害抬高。

新引擎用双边事件队列解决这些问题，并把失败、双杀和超时纳入结果。当前 YAML 保留了“策划初稿”参数，运行报告后即可看到各敌人是否落入目标区间。

## 数据诊断流程

1. 在等级检查点比较三职业胜率、TTK 和有效 DPS。
2. 查看 P10/P50/P90，判断均值相近时是否存在过强波动。
3. 用技能伤害占比和 CD 利用率定位技能循环断档。
4. 对核心技能倍率和敌人 HP/攻击做 ±5%/±10% 弹性分析。
5. 使用全局采样确认局部结论是否在更大参数范围内成立。

## 调参方案

自动调参搜索三个职业核心爆发技能、三类敌人 HP，以及精英/Boss 攻击。推荐方案由 TTK、胜率、职业差异和改动成本共同决定。Pareto 表保留其他合理取舍，例如“更接近目标胜率但职业差异略大”的方案。

## 前后对比

通过以下命令生成真实对比数据：

```powershell
python -m combat_balance --config configs/portfolio_arpg.yaml report --runs 1000
python -m combat_balance --config configs/portfolio_arpg.yaml optimize
```

`configs/initial_draft.yaml` 通过一层配置继承复现人工初稿，`configs/portfolio_arpg.yaml` 是完成诊断后的平衡版本。分别生成报告即可获得可复现的前后对比；`artifacts/optimization/validation.csv` 则用于复核算法候选。

固定 seed `20260908`、Lv30、每职业每敌人 1,000 场的前后对比如下：

| 敌人 | 初稿阵容胜率 | 初稿 TTK | 初稿职业 DPS 差 | 平衡版阵容胜率 | 平衡版 TTK | 平衡版职业 DPS 差 |
|---|---:|---:|---:|---:|---:|---:|
| 普通怪 | 100.0% | 8.80 秒 | 23.1% | 100.0% | 9.26 秒 | 5.4% |
| 精英怪 | 100.0% | 34.32 秒 | 27.1% | 78.0% | 26.19 秒 | 6.2% |
| Boss | 66.2% | 134.37 秒 | 30.2% | 59.4% | 94.59 秒 | 7.3% |

平衡版三类敌人的阵容指标均进入目标区间，职业 DPS 差距也低于 8% 软上限。完整优化流程随后以 10,000 场总样本复核，仍选择人工平衡版基线作为改动成本最小的可行方案。

## 设计取舍

- 不追求三个职业完全相同的平均数，否则职业差异会被抹平。
- Boss 胜率不单靠提高 HP 控制，因为那只会拖长战斗；攻击压力和防御技能价值也必须进入模型。
- 自动调参只改少量高杠杆参数，改动成本作为目标之一，避免生成难以维护的碎片化数值。
- 统计显著不等于体验一定更好；动画反馈、操作难度和关卡机制仍需在实际原型中验证。
